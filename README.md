## What is Qyvaria?

**Qyvaria** is a public open-source AI software project built around three connected ideas:

1. **Qyvaria AI Software** — the engineering layer for prompts, agents, model workflows, local AI, monitoring, command routing, release documentation, and software-building support.
2. **Qyvaria OS** — the operating-system-style AI workspace, built around a browser-native shell and modular UI environment.
3. **`qyvaria.py` Kernel Corpus** — a single-file Python artifact that acts as a portable software corpus, command runtime, prompt-generation system, and kernel bridge.

The project is designed for the future of practical AI work: not just one prompt, not just one model, and not just one screen, but a complete workspace where AI can be connected to files, tools, code, documents, voice-ready interfaces, monitoring systems, vaults, agents, and local execution.

Qyvaria is experimental, but it is not vague. It is a real software structure with public releases, code artifacts, licensing, installer materials, local AI integration goals, and a clear direction: **AI should become an inspectable engineering environment controlled by the human user.**

## Qyvaria AI Software

**Qyvaria AI Software** is the AI engineering layer of the project. It is where prompt tooling, local AI workflows, model bridge concepts, agent orchestration, software engineering support, documentation, monitoring, and release logic come together.

The goal is to make AI workflows more:

- **local** — able to work near the user's own machine, files, folders, and models;
- **structured** — using clear commands, prompt fields, engine modes, logs, and release files;
- **inspectable** — giving the user a way to see what is happening and why;
- **repeatable** — supporting seeds, defined engine settings, command patterns, and documented outputs;
- **modular** — allowing separate components to evolve without hiding the architecture;
- **human-controlled** — putting the user in charge of execution, review, publishing, and safety.

Qyvaria AI Software is not only about generating text or images. It is about building an engineering environment where AI can be part of a workflow: reading context, preparing prompts, routing commands, organizing files, supporting code, monitoring runtime behavior, and helping the user build a larger system.

### Core AI software capabilities

- Prompt generation for structured image and text workflows.
- Engine-aware prompt wrapping for SDXL, Midjourney, Flux, and generic modes.
- Local AI integration concepts for model routing and offline-capable work.
- QyChat assistant environment for interactive AI work.
- Agent and neural workspace infrastructure for orchestration experiments.
- Runtime monitoring concepts such as heartbeat, telemetry, logs, and panels.
- Vault and workspace organization for project materials.
- Kernel communication between UI, local runtime, and AI modules.
- Release documentation for GitHub, open-source publication, and project clarity.
- Ethical release structure with license, notice, credits, and no-secrets guidance.

## Qyvaria Python Kernel Corpus

The **Qyvaria Python Kernel Corpus** is the portable runtime center of the project. The public file is named:

```bash
qyvaria.py
```

The kernel is designed as a **single-file Python bundle**. That means it can carry many pieces of software and documentation logic inside one artifact, making it easier to move, inspect, archive, release, and execute.

The uploaded kernel context identifies the bundle as:

```text
name: qyvaria
format: py-single
entry: qyvaria
total_files: 277
```

A single-file kernel corpus is useful because it gives Qyvaria a portable center. Instead of scattering the identity of the project across many disconnected fragments, Qyvaria can keep a compact executable layer that represents the core logic.

### What the kernel does

The kernel can support:

- prompt generation,
- structured prompt fields,
- engine-specific wrappers,
- command-line execution,
- output to stdout,
- optional JSON output,
- optional TXT output,
- deterministic seed-based generation,
- safety negative terms,
- style packs,
- persona tone settings,
- local runtime bridge concepts,
- and future integration with Qyvaria OS.

### Basic command

```bash
python qyvaria.py --subject "futuristic tram in Prague" --style cinematic --engine sdxl -n 4
```

### Deterministic command

```bash
python qyvaria.py --subject "isometric eco-city block" --style pixel --engine generic -n 4 --seed 42
```

### Output files


## Prompt generation engines

The `qyvaria.py` prompt system supports multiple engine modes:

| Engine | Purpose |
|---|---|
| `sdxl` | Structured positive/negative prompt output with generation parameters. |
| `midjourney` | Prompt text wrapped with Midjourney-style flags. |

Prompt generation in Qyvaria is designed to be more structured than normal prompt writing. It uses fields such as camera, composition, lighting, materials, mood, palette, scale, and negatives. This gives artists, engineers, and AI users a reusable framework.

## Compression and corpus packaging

Qyvaria explores **compact corpus packaging**. The point is not to promise impossible compression for every file. Images, videos, archives, and already-compressed binaries may not shrink much. But code, text, logs, documentation, repeated structures, serialized corpora, and patterned software materials can sometimes compress very strongly.

The Qyvaria philosophy is:

> A large software or knowledge structure should be able to become a smaller, portable, inspectable, release-ready corpus when the content is compressible and well organized.

This is why Qyvaria talks about turning hundreds of megabytes into tens of megabytes in favorable cases, or reducing gigabyte-scale structured material into smaller MB-range packages when the data has repetition and compressible structure.

Compression is useful for:

- moving project corpora,
- archiving release material,
- transporting documentation,
- bundling many small files,
- reducing overhead,
- preserving public artifacts,
- and creating AI-ready packages.

## Ethics, safety, and responsible release

Qyvaria should be powerful, but it should also be careful. Strong AI software needs strong ethics.

### Hard ethics principles

- The human user remains in control.
- Do not publish secrets.
- Do not upload private keys, API keys, passwords, tokens, credentials, private logs, private customer data, proprietary datasets, or confidential files.
- Clearly label experimental features.
- Credit open-source software.
- Respect third-party licenses.
- Keep public release materials separate from private local data.
- Avoid claiming production certification where there is only research or alpha software.
- Use local AI carefully and review outputs before publishing.
- Treat monitoring, logs, and telemetry as sensitive where they may contain user context.
- Keep medical, legal, financial, emergency, and safety-critical uses outside unsupported claims.

Qyvaria is a public evolving software project. Public release does not mean every subsystem is production-certified. The responsible way to publish Qyvaria is to show the vision clearly while also being honest about experimental status.
